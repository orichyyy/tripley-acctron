## Current architecture direction

The repo is building a TypeScript framework for kiosk/web-container applications. Core code should depend on framework ports and registries, not raw browser, React Router, native SDK, or device SDK APIs.

Important boundaries:

- Raw `@tripley-kit/native` should be wrapped only by `packages/native-adapter`.
- Business code, plugins, Flow nodes, UI adapters, and kiosk example code should depend on framework ports such as `NativePort`, `DeviceRegistry`, `InputSourceRegistry`, `TtsPort`, `WindowPort`, and command/condition/flow registries.
- CEN/XFS device operations should not be proposed as `@tripley-kit/native` APIs. They should be wrapped from `@tripley-kit/xfs-client` into framework device/input adapters.
- Core Flow `UserInput` must not hard-code devices such as pinpad or barcode reader. It must use registry lookup only.

## Native SDK integration status

There is currently no direct dependency on `@tripley-kit/native` in `package.json` or `pnpm-lock.yaml`.

Current state:

- `packages/native-adapter` defines `@tripley-kit/web-container-native-adapter`.
- `TripleyNativeAdapter` accepts a raw native object as `unknown`, validates the expected SDK shape, and exposes `NativePort`.
- Docs say only the native adapter package should wrap raw `@tripley-kit/native`; all other packages should depend on `NativePort`.

If real native SDK integration is added later, it should be isolated to `packages/native-adapter`, likely through a factory that imports `@tripley-kit/native` and returns `NativePort`.

## Constraints and conventions to preserve

- Follow `AGENTS.md`: keep files focused, split modules before appending large unrelated logic, avoid hidden global mutable state, keep business logic framework-independent.
- Do not make core depend directly on React Router, browser `window.open`, raw native SDK, or raw XFS client.
- Prefer registries and ports over hard-coded device names.
- Use safe summaries for secure input. Never log raw PIN or sensitive track data.
- Preserve optional input source behavior for devices such as QR/barcode.
- Preserve timeout/interrupt cleanup behavior for active input source sessions.
- Prefer small package-level tests over only example-level tests.
